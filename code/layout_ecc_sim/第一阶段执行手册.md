### 2.3 执行步骤

1. **探查先行**：先用脚本统计 `hier_cell` 的模式分布，不要急着写解析规则。

```powershell
cd code\layout_ecc_sim

import csv, re, collections
pat = collections.Counter()
with open('data/layout/p1_ooc_win/primitive_map.csv', encoding='utf-8') as f:
    for row in csv.DictReader(f):
        h = row['hier_cell']
        m = re.match(r'u/s(\d+)/', h)

```

确认 s1–s10 覆盖了多少原语，toplevel 和其他前缀有多少。

1. **写解析器**：新建 `layout_ecc/stage_tags.py`：

```python
"""hier_cell -> (stage_id, module_role, replica_id) 解析。

规则只认 P1 设计实际出现的层次名；解析不出的一律 unknown 并计数，
不许猜。规则改动必须重跑 unknown 占比报告。
"""
import re

_STAGE = re.compile(r"^u/s(\d+)/")
_ROLE_KEYS = [
    ("complete_butterflies", "butterfly"),
    ("pipe_rot", "twiddle"),
    ("rot", "twiddle"),
    ("mem", "delay"),
    ("hold_r", "control"),
]
_REPLICA = re.compile(r"replicas\[(\d+)\]")


def tag(hier_cell):
    m = _STAGE.match(hier_cell or "")
    if not m:
        return -1, "unknown", None
    stage = int(m.group(1))
    role = "unknown"
    for key, r in _ROLE_KEYS:
        if key in hier_cell:
            role = r
            break
    rep = _REPLICA.search(hier_cell)
    return stage, role, (int(rep.group(1)) if rep else None)
```

注意 `_ROLE_KEYS` 的顺序就是优先级：`complete_butterflies` 里嵌套的 `pipe_rot` 应该标 twiddle 还是 butterfly，**先按嵌套语义想清楚再定顺序**，并在注释里写下理由。

1. **接入** `layout_import.py`：导入 CSV 时调 `tag()`，按 Site 内多数原语的 stage 定 Site 级标签；同 Site 出现多个 stage 时标 `is_shared=True` 并记录 stage 集合。把 `stage_id`、`module_role` 填进 tile 字典（替换现在的 `-1` / `"placed"`）。
2. **查看器按级着色**：10 级用 10 色渐变（建议 HSV 等距），图例列出 s1–s10；保留"按资源类型/按 FFT 级"两种着色切换。悬停气泡加 stage 和 role。
3. **unknown 报告**：命令行打印 unknown 原语数和占比，按 `ref_name` 列出前 20 个 unknown 类型，人工判断该不该入规则。

### 7.2 WP1 怎么做的

**探查（手册 2.3 第 1 步，先于写规则）。** 用手册给的 `hier_cell` 前缀统计：全部 140907 条原语都匹配 `u/s(\d+)/`，没有 toplevel 残留。各级计数：

s6=16676 s7=17338 s8=18591 s9=9507  s10=11228

s8 偏大、s9 偏小，对应 P1 的 stage 8/9 TMR 副本，不是探查脚本写错。第 2.2 节的层次名样例与这份 CSV 一致，没有触发 §6「设计版本变了」停止条件。

再按第一段 token 看 role：手册草稿里那 5 个关键字（`complete_butterflies` / `pipe_rot` / `rot` / `mem` / `hold_r`）只能盖住大约六成，**(no_key) ≈ 55131（约 39%）**，直接当规则会远超 unknown < 5%。所以没有用草稿 5 条交差，而是对着 `experiments/※seven_arch_rtl/P1/hdl/rtl/top_p1_kernel.sv` 把实际出现的名字补进规则，解析不出的仍标 `unknown`。

**优先级（手册点名要想清楚的嵌套）。** 2.2 节例子 `complete_butterflies[3].pipe_rot.rotate` 的语义是「蝴蝶实例里的旋转」，应标 **twiddle 而不是 butterfly**。规则因此是 twiddle 关键字先于 `complete_butterflies`；同理 `replicas[i].u/rot2` 先标 twiddle，再才是 replica。`u_apply` / `sy*` / `res*` / `app_*` 走算术 ECC 路径，单独成 role `ecc`（手册 2.1 问的是 butterfly/delay/twiddle/control/replica，但 G1 允许明确功能标签；不标 ecc 的话 s10 几乎全 unknown）。

**规则收敛过程（不许猜，靠计数）。**

| 轮次 | unknown role | 原因 |
|---|---|---|
| 手册 5 关键字 | ~39% | 大量 `sy/res/u_apply/replicas/q*` 未覆盖 |
| 加 RTL 名，但用了短串 `qu`/`al` | 9.12% 后又乱标 | `qu` 命中 `request`，`al` 命中 `valid`；改为 `qu[0-5]`、`au0` 这类带编号的正则 |
| 加 `g_sync_distributed`、`out*_re`、`phase` 等 | 6.25% | 剩下几乎全是级顶层扁平化 LUT 锥 `ii_s*` / `rr_s*` |
| 把 `ii_s`/`rr_s` 标 twiddle | **0.02%（22 条）** | 见下 |

`ii_s`/`rr_s` 不是瞎猜：它们**只出现在 s2–s7**（有通用 twiddle 乘法的级）；s1（`TRIVIAL_ONLY`）、s8–s10 为 0。蝴蝶加法 LUT 已经在 `complete_butterflies/` 下面。因此把这两类级顶层 real/imag LUT 锥记为 twiddle，并在 `stage_tags.py` 注释里写下这条观察。若以后换网表，必须重跑 unknown 报告。

最终 unknown 22 条：8 GND + 8 VCC + 6 个 `ml*` LUT。前 20 类 `ref_name` 看过，GND/VCC 是常量绑，`ml*` 未再扩规则。完整打印在 `data/layout/p1_ooc_win/unknown_report.txt`。命令：`python -m layout_ecc.stage_tags`。

### 7.3 WP2 怎么做的

**只复用、不改冻结注入器。** 读了 `experiments/fault_injection_1024/projects/P1/run_p1.py` 和 `common/python/campaign_support.py` / `protection.py` / `fixed_fft.py`。本包 wrapper 是 `layout_ecc/functional.py`，用 `sys.path` 导入实验树，**零修改** `experiments/`。

**黄金基准。** 帧规格与冻结 trial set 的 `random_seeded` 相同：`uniform_random`，seed **20260721**，范围 ±1048576。写入 `data/golden/p1_random_seeded.json`（输入 + 十级后定点输出）。SHA-256：

```text

```

零故障再跑一遍，输出与文件逐字相同。cycle 第一版未做到时钟，只用帧内相对位置（手册允许）。

**扫级。** `python scripts/wp2_stage_scan.py` → `data/wp2_stage_scan.json`。每一级翻 **bit 0**（LSB）一个代表性 FF：s1–s7/s10 走算术 [6,4,3] → 全部 CORRECTED；s8/s9 走 TMR → MASKED。开环 LSB 偏差只有 0 或 1，因为后续级还有 `>>>1`，LSB 几乎被量化掉——**不能**用 bit0 判断「哪一级最敏感」。

**RTL 核对（手册 3.2 第 5 步）。** 改用 **bit 20、protection=off** 开环续跑剩余级。偏差随级号倍增，末级最大，与「后面级剩余缩放更少」一致，**没有**触发 §6「末级翻转完全无影响」：

```text
s1=2048 s2=4096 s3=8192 s4=16384 s5=32768
s6=65536 s7=131072 s8=262144 s9=524288 s10=1048576
```

记在 `data/wp2_rtl_check.json`。阈值 2 vs 3：LSB 扫级时 `frac_over_threshold_*` 全是 0，只说明 LSB 不够；阈值认识线要用高位或更大误差，不要把 bit0 表当成阈值结论。

**四类结局（各至少一次，机制如下）。**

|---|---|---|

| SDC | s10 `protection=off` | 不再走 ECC，输出已经偏了且没有检测标志 |

### 11.1 WP8 怎么做的

`layout_ecc/units.py` 是唯一换算出口。

**RPM→µm。** UG474/DS180 没有 7 系列 RPM 步长。标 `assumption:`：区间 4–16 µm（65 nm CLB 量级 10–30 µm 按 28/65 缩放，再给 DSP/BRAM 列留余量），名义值 **8 µm**（区间中点）。不是 xc7vx690t 实测。

**Radaelli 四点**（经 Ebrahimi DAC'13 Table 1）：22/47/95/144 MeV → 1.178/1.902/2.903/4.613 µm²。对数最小二乘 \(A=c E^{\alpha}\)：**α = 0.7015**（亚线性），RMSE = 0.227 µm²。6.5× 能量对应约 3.9× 面积，与手册预期一致。

**能量≠LET。** 桥是显式假设，不是静默换算：\(A(\mathrm{LET})=2.903\,(\mathrm{LET}/15)^{\alpha}\) µm²，15 是旧 GUI 默认 LET，2.903 是 Radaelli 95 MeV 点。指数从中子能量拟合挪过来，**不**声称 15 MeV·cm²/mg ≡ 95 MeV 中子。

`run_strike(..., kernel_model="anchored")`：由 A 得正入射圆 \(a=\sqrt{A/\pi}\)，再 `/ RPM_TO_UM` 成格，θ 仍按 \(1/\cos\theta\) 拉长。`legacy_linear` 仍是 `a0 + k_let·LET`。

手扫：θ=45°，LET∈{5,10,15,20,30}，**均匀占用中心** 20 seed（不钉质心）。`data/wp8_kernel_compare.json`。

| LET | A(µm²) | legacy 覆盖 Site | anchored 覆盖 Site | 高估倍数 |
|---|---|---|---|---|
| 5 | 1.34 | 128 | 1.00 | 128× |
| 15 | 2.90 | 172 | 1.00 | 172× |
| 30 | 4.72 | 238 | 1.00 | 238× |

SRAM 簇面积在 8 µm/格下半径 < 1 格，所以 anchored 几乎总是 1 个 Site。WP3 用 a0=4–20 格的线性核，比文献 SRAM MBU 面积大约两个数量级。这是模型误差，不是统计涨落。

### 11.2 WP9 怎么做的

`layout_ecc/mbu_patterns.py`：

- P(k=1)=0.70、P(k=2)=0.30。来源 Pérez-Celis & Wirthlin, **IEEE TNS 2021**（中子 MCU 占事件 30%）。该文没有 3/4 bit 拆分，MCU 一律记 k=2（聚类的下界）。
- 旁表：Mayo et al. **IEEE TNS 2025** Versal 7 nm，LET=62.4 时 σ_SBU≈σ_2bit；默认扫描仍用 7 系列中子表。
- 域间权重 `bit_weight = bits`，注释标 assumption：几何近邻先选，域按该行位数占比。

`flip_model="pattern"`：先采 k，再在核内候选 (Site×域) 里选 k 条。形状 `cluster`（距中心升序）对照 `uniform`。

真 Radaelli 核只有 1 个 Site，k=2 只会打到同一 Site 的两个域（同一 `symbol_id`），「同码字多符号」看不见。扫描因此另加 **A=1300 µm² 地板**（约 2.5 格半径），只为让邻居 Site 进核，并在 JSON 里标 assumption。

20 seed、同一批均匀中心、anchored+地板，`data/wp9_pattern_compare.json`：

| 模型 | 平均翻转条数 | 跨级率 | 同码字多符号率 |
|---|---|---|---|
| bernoulli（P_DEFAULT≈0.3/域） | 3.50 | 0.05 | **0.10** |
| pattern cluster | 1.20 | 0.00 | 0.00 |
| pattern uniform | 1.20 | 0.00 | 0.00 |

和「伯努利低估多重数」的文献叙事相反：那是 **按 bit、p 很小** 的 CRAM 注入。这里是 **按 Site×域、p≈0.3**，一枚硬币就能翻掉核里好几行，比「70% 只翻 1 条」的图案表更密。同码字多符号在这 20 次里只出现在伯努利侧。WP7 若上图案模型，必须先把 p 降到 bit 级，或接受 Site 级伯努利会高估多符号。

### 12.1 两份 σ 材料的分工（不许混用）

| BRAM | **5.57 × 10⁻¹⁵ cm²**（±18%） | 1.8 | 45 | 42 |
